# JobBot v0.5 发布说明

## 总览

v0.5 将 JobBot 扩展为全面的 Web-UI 求职平台，新增职位发现、批量操作、市场情报和仪表板分析。Web UI 现在是**主要界面**——`pnpm jobbot ui` 启动你所需的一切。CLI 命令保留用于脚本和自动化。

## 新功能

### 职位搜索发现 (`pnpm jobbot discover`)

跨多个招聘网站搜索职位：

```bash
pnpm jobbot discover --query "后端工程师" --location "北京"
pnpm jobbot discover --query "机器学习" --source greenhouse --source lever
pnpm jobbot discover --query "SRE" --location "远程" --ingest  # 自动添加到流水线
```

- **LinkedIn**：通过 cheerio 解析 HTML —— 按关键词 + 地点搜索职位
- **Greenhouse**：公共看板 API (`boards-api.greenhouse.io`) —— 按公司搜索
- **Lever**：公共职位 API (`api.lever.co`) —— 按公司搜索
- **Ashby**：公共 API (`jobs.ashbyhq.com/api/nonuser`) —— 按公司搜索
- 并行向所有启用的数据源发起请求（`Promise.allSettled`）
- 按 URL 去重
- `--ingest` 标志自动将结果添加到流水线
- Web UI 集成：添加 URL 页面上的搜索表单，带行内"+"添加按钮

### 批量添加链接

一次添加多个职位链接——不再逐条复制粘贴：

- **Web UI 页面** `/add-urls`：粘贴链接（每行一条），预览 ATS 检测结果，一键全部添加
- **"添加并运行流水线"** 按钮：添加链接后立即触发完整流水线提取
- **CLI**：`pnpm jobbot add-url <url1> <url2> <url3> ...` 支持多个位置参数
- **API**：`POST /api/jobs/add-urls` 和 `POST /api/jobs/add-urls-and-run`
- 结果显示：新增（✓）、重复（⚠）、错误（✕）按链接分类

### 职位市场情报

`job_market_data` 表现在每次打分后自动填充：

- **薪资范围** — 从职位描述中用正则表达式提取（如 `$120k–$180k`），键为 `salary_range.{职位}.{地点}`
- **常见要求** — 所有职位中的技能/技术出现频率（`common_req.{技能}`），使用候选人资料中的技能列表
- **职位名称频率** — 标准化职位名称分布（`title_freq.{职位名称}`）
- confidence 和 sample_size 随时间跟踪数据可靠性
- **CLI**：`pnpm jobbot market-data [--key <前缀>]` 查看当前情报
- **API**：`GET /api/market-data?key=<前缀>`
- 集成到所有打分路径：`runScore()`、`runJob()`、服务器步骤处理器、重新生成处理器

### 仪表板分析图表

仪表板现在包含内联 SVG 分析图表（无需外部图表库）：

- **等级分布** — 水平柱状图，显示 A/B/C/D 数量和百分比
- **流水线漏斗** — SVG 漏斗可视化：已录入 → 已提取 → 已打分 → 已制作 → 已审核，宽度按比例
- **热门公司** — 列出你流水线中发布职位最多的公司
- 所有数据来自现有 SQLite 查询 — 轻量且即时

### 简历变体

根据职位名称关键词自动选择最佳简历变体：

- 从 `candidate.yaml`（`resume_variants` 区域）读取可用的变体
- 基于关键词匹配：后端、全栈、前端、机器学习、DevOps、移动端
- 职位名称关键词权重大于职位描述关键词
- 传递路径：`composeJob()` → `tailorJob()` → LLM 提示词作为聚焦指令
- 无明确匹配时回退到 `general`

### 求职信语气

为 AI 生成的求职信选择语气：

- **专业**（默认）：精炼、平衡的商务语气
- **热情**：积极、温暖、展现真诚的兴趣
- **简洁**：直接、简短段落、不冗余 — 最多 3 段

```bash
# CLI：自动使用默认（专业）语气生成
pnpm jobbot cover-letter --job <id>
```

- **Web UI**：职位详情页上生成求职信前可选择语气
- **API**：`POST /api/jobs/:id/cover-letter` 带 `{ tone: "professional" | "enthusiastic" | "concise" }`

### 定时流水线运行

按计划自动运行流水线：

```bash
pnpm jobbot schedule --once                    # 运行一次流水线
pnpm jobbot schedule --interval 360            # 每 6 小时运行一次（Ctrl+C 停止）
```

- **服务器内**：`POST /api/schedule/start` / `POST /api/schedule/stop` / `GET /api/schedule/status`
- 使用 `setInterval` — 无需外部依赖
- 每次触发运行完整流水线（`runAll()`）

### 投递步骤研究

为 v1.0 投递自动化做准备——详见 `docs/apply-research.md`：

- **ATS 表单结构** 文档化：Greenhouse、Lever、Ashby、Workday、LinkedIn
- **字段映射** 已编目：标准字段 + 各平台的 EEO/人口统计
- **适配器接口** 已设计：`AtsAdapter` 含 `canHandle()`、`detectForm()`、`fillField()`、`uploadResume()`、`submit()`
- **实现优先级**：Lever → Greenhouse → Ashby → Workday
- **反爬措施** 已识别：CAPTCHA、蜜罐、会话超时
- 所有适配器桩已更新 v1.0 实现说明

### LLM 提取薪资与技能

提取步骤现在使用 DeepSeek 解析职位描述中的薪资范围和要求技能——不仅仅是正则表达式。在提取期间写入 `job_market_data`（置信度 0.8），正则表达式作为旧职位的回退方案。

- **薪资**：LLM 以完整上下文识别 `$120k–$180k` 模式，处理非标准格式
- **技能**：LLM 识别招聘信息中提及的技术，而不仅仅是固定关键词列表
- **职位详情页**：每职位薪资醒目显示，技能以标签芯片展示并标注 LLM/正则来源
- **每职位市场数据**：查询 `source = job_<id>` 获取该职位的特定提取数据

### 个人资料 AI 编辑差异视图

通过 AI 编辑个人资料 YAML 时，现在可以查看**并排差异对比**，而不仅仅是原始输出：

- **基于 LCS 的逐行差异**：左侧为旧版 YAML，右侧为 AI 建议的 YAML
- **颜色高亮**：新增行为绿色，删除行为红色，未更改行为灰色
- **变更摘要**：顶部显示"+N 新增 · −M 删除"
- **可滚动面板**：两侧在 500px 容器内独立滚动
- 单击即可应用或放弃

### 可配置 LLM 模型

DeepSeek 模型现在可通过 `local/config.yaml` 配置：

```yaml
deepseek_model: deepseek-v4-pro  # 默认（最佳质量）
# deepseek_model: deepseek-v4-flash  # 更快、更便宜
```

所有 LLM 调用（提取、评分、定制、求职信、审核、个人资料 AI 编辑）都读取此设置。无硬编码模型字符串。`deepseek-chat` 和 `deepseek-reasoner` 上游已弃用（将于 2026/07/24 下线）。

### 错误修复

- **删除外键约束**：`deleteJob()` 现在在删除职位前正确清理 `events` 行，修复了"FOREIGN KEY constraint failed"错误
- **差异视图滚动**：修复了个人资料 AI 编辑并排对比中 `overflow: hidden` 阻止滚动的问题

## 破坏性变更

无。所有 v0.4 命令和 API 路由继续工作。新功能均为增量添加。

## 从 v0.4 迁移

无需数据库迁移。`job_market_data` 数据在职位打分时自动填充。简历变体和求职信语气为可选功能——现有行为保持不变。
