# JobBot v0.6 发布说明

## 总览

v0.6 是一个基础性版本，引入了**多用户支持**、**并行流水线执行**、**实时流水线监控**和**投递生命周期追踪**。个人资料从 YAML 文件迁移到数据库，流水线全面并发化并支持单任务取消。

## 新功能

### 并行流水线执行

流水线现在在每阶段内**并发**处理职位，不再顺序执行：

- **`asyncPool`** 工具 — 通用滑动窗口并发池，支持 AbortSignal、进度回调、结果追踪
- 每阶段并发限制（可在 `local/config.yaml` 配置）：extract=10、score=10、compose=5、audit=5
- **每用户独立流水线** — 每个用户拥有自己独立的流水线，多用户可同时运行互不干扰
- **全局并发上限**（默认 50）防止多用户同时运行时系统过载
- 移除了人工 `delay()` 调用 — 并发池的自然限流替代了它
- **自动重试**临时性 LLM 错误（空响应、网络错误），每作业一次重试

### 实时流水线监控

流水线页面（`/pipeline`）现在可以实时显示运行进度：

- **实时状态面板** — 每阶段进度条（提取/打分/制作/审核），显示 ✓/✕/▶ 计数
- **任务池表格** — 列出每个正在运行的任务：职位 ID、阶段、标题/公司、状态、耗时
- **单任务取消** — 取消单个卡住的作业，不影响整个流水线
- **取消整个流水线** — 停止全局流水线，已在运行的任务正常结束
- 每秒通过 `GET /api/pipeline/status` 轮询，完成后自动刷新

### 多用户模式

职位**按用户隔离** — 每个用户发现和添加自己的职位池。打分、定制和投递追踪全部按用户独立：

- **`users` 表** — 用户账户（id、name、active、created_at）
- **`user_scores` 表** — 每用户职位评分（每用户+职位唯一）
- **每用户职位** — `jobs` 表新增 `user_id` 列；同一 URL 可被不同用户添加
- **`user_preferences` 表** — 每用户个人资料存储（候选人、偏好、答案以 YAML 文本存于 SQLite）
- **自动迁移** — v0.5 现有数据分配给 `default` 用户（id=1）
- **CLI 命令**：`pnpm jobbot user-list`、`user-add <name>`、`user-switch <name>`，score/list/run/tailor/compose 支持 `--user` 标志
- **Web UI 用户切换器** — 导航栏下拉菜单 + 添加用户弹窗；通过 Cookie 持久化
- 仪表板和职位详情页显示每用户评分
- 删除保护 — 用户只能删除自己的职位（否则返回 403）

### 投递生命周期追踪

追踪每份职位投递的完整生命周期：

- **状态流转**：`draft → submitted → replied → interview → offer → accepted / rejected`
- **职位详情页** — 新增"投递追踪"卡片，显示当前状态、投递日期、回复类型
- **回复按钮** — 标记已投递后："已回复"、"面试"、"Offer"、"被拒"；收到 Offer 后可选择"已接受"/"已拒绝"
- **仪表板筛选** — "隐藏已投递"（默认）、"显示全部"、"仅已投递"
- **API 接口**：`POST /api/jobs/:id/apply`、`POST /api/jobs/:id/response`、`GET /api/jobs/:id/application`
- 每次状态变更均记录事件

### 个人资料存储迁移至数据库

个人资料从 `local/profile/` 中的 YAML 文件迁移到 SQLite 数据库：

- **`user_preferences` 表** — 以 TEXT 形式存储 candidate.yaml、preferences.yaml、answers.yaml
- **`profile-store.ts`** — `readCandidate()`、`readPreferences()`、`readAnswers()`、`writeProfile()`，自动创建行
- **`local.example/profile/`** 已删除 — 个人资料不再存放在磁盘文件
- 所有 LLM 调用方（评分、定制、求职信、市场数据）通过 `getActiveUserId()` 从数据库读取
- Web UI 个人资料编辑器直接读写 `user_preferences` — 无需管理 YAML 文件

### 可配置推理模式与并发

通过 `local/config.yaml` 精细控制 LLM 推理和流水线并行：

```yaml
deepseek_thinking:
  default: auto
  operations:
    score: disabled       # flash 模型，评分任务简单直接
    extract: disabled     # 结构化提取，无需推理
    tailor: enabled       # 复杂简历定制受益于推理
    cover-letter: enabled # 创意写作受益于推理
    audit-content: enabled

concurrency:
  global: 50              # 所有用户的最大并发任务总数
  per_user: 10            # 每用户流水线最大并发作业数
  stages:
    compose: 5            # pdflatex 消耗 CPU
    audit: 5              # pdflatex + 视觉 API
```

- DeepSeek v4-pro `thinking` 模式可按操作分别配置
- 打分默认使用 `deepseek-v4-flash`（更快，无需推理）
- 所有 `max_tokens` 提升：extract/tailor/cover-letter/audit 为 16384，score 为 8192

### 健壮的 LLM JSON 解析

新增 `parseLLMJson()` 工具，替代整个代码库中的原始 `JSON.parse`：

- 处理 **Markdown 代码块**（` ```json ... ``` ` 或 ` ``` ... ``` `）
- 提取**嵌入在文本中的** JSON 对象/数组
- **失败时输出调试信息** — 将原始 LLM 响应打印到 stderr 以便排查
- 处理 `reasoning_content` 溢出 — 检测 DeepSeek 的思维链是否超出 token 预算，抛出清晰错误

### 审核改进

- **尝试计数** — 审核反馈文件现在记录 `attempt` 计数器（1-3）
- **最终失败状态** — 3 次尝试失败后，职位状态设为 `audit_failed`（不再无限循环）
- **反馈自动清理** — compose 消费并删除反馈文件；如果审核再次失败，会写入新的反馈文件
- **每职位目录** — audit.json、audit-feedback.json 和页面截图全部存放在 `local/resumes/<jobId>/`

### 流水线 UI — 交互式阶段控制

职位详情页新增交互式流水线控制：

- **"运行流水线"按钮** — 通过 `POST /api/run` 带 `{jobId}` 为单个职位运行完整流水线
- **可点击的流水线阶段** — 点击任意阶段（提取/评分/制作/审核）从该点重启。过去的阶段显示"从 [阶段] 重启"，当前阶段显示"重新 [阶段]"
- **`POST /api/jobs/:id/run-from`** 接口 — 将职位重置到目标阶段之前，仅对该职位运行流水线（不像 `/api/run` 处理所有符合条件的职位）

### 委员会审核系统

单一内容审核替换为**3 名独立审核员组成的委员会**，各具不同视角：

| 审核员 | 权重 | 关注点 |
|---|---|---|
| ATS 筛选员 | 30% | 关键词匹配、ATS 兼容性、需求对齐 |
| 招聘经理 | 40% | 经验质量、影响力量化、竞争力评估 |
| 格式审核员 | 30% | 单页检查、结构、可读性、LaTeX artifact |

- 审核员通过 `Promise.all` 并行运行
- 分数加权平均；显示个人审核员分数（如 `ATS Screener 55 | Hiring Manager 48 | Format Reviewer 90 → Overall 63/100`）
- `Promise.allSettled` 确保一个审核员失败不会影响整个委员会
- 三个专用提示文件：`prompts/audit-ats.md`、`audit-hm.md`、`audit-format.md`

### 定制 — LLM 激进重写简历

"tailor" 步骤重命名为 **"customize"**，LLM 现在被指示激进地重写关键点：

- **合并、拆分和改写**关键点以匹配职位描述的语言
- **选择展示哪个项目**并为其定制亮点
- **重试时将上一版输出反馈给 LLM** — LLM 可以看到之前写的内容，进行针对性修改
- 审核反馈移至提示词**顶部**，优先级最高
- 重试时使用 **32K max tokens**（首次尝试为 16K）
- 定制操作启用推理模式（`customize: enabled`）

### 简历模板 — 重大修复

- **不再有图标渲染 artifact** — 移除 fontawesome5，联系信息使用管道分隔纯文本，完全兼容 ATS 解析
- **章节顺序修复** — 有经验的候选人先展示工作经验再展示教育
- **项目名称 Bug 修复** — 占位符从 `{{name}}`（与姓名冲突）重命名为 `{{project_name}}`
- **技能分类** — 新增 `Data Processing` 类别（Spark、Hadoop、Hive 不再错误归类为"数据库"）
- **求职信段落间距修复** — 修复 PDF 渲染中的 `\textbackslash{}n` artifact
- **10pt → 11pt** 提升可读性；收紧边距以补偿空间
- **项目部分** — 始终展示（1 个项目，由 LLM 选择），带定制亮点

## 破坏性变更

- **个人资料 YAML 文件已移除。** `local.example/profile/` 已删除。个人资料现在存储在 SQLite 数据库（`user_preferences` 表）中。v0.5→v0.6 迁移自动处理 — 现有个人资料**不会**自动迁移（它们在 `local/` 目录中，需要重新输入或复制粘贴）。
- **`CANDIDATE_PATH` / `PREFERENCES_PATH` / `ANSWERS_PATH` 导出已移除**。请改用 `src/utils/profile-store.ts` 中的 `readCandidate()` / `readPreferences()` / `readAnswers()`。
- **简历文件布局变更。** 文件现在存放在 `local/resumes/<jobId>/` 而非平铺在 `local/resumes/`。旧文件不会移动 — 重新执行 compose 来生成。
- **URL 唯一性现在是每用户的。** 两个不同用户可以添加相同的职位 URL。如果你的脚本依赖全局 URL 唯一性，请按用户更新。

## 从 v0.5 迁移

下次运行时自动执行（通过 `init-db` 或任何打开数据库的命令）：

1. 创建 `users` 表，创建 `default` 用户（id=1）
2. 创建 `user_scores` 表，现有评分迁移至默认用户
3. 为 `jobs`、`resume_versions`、`applications` 添加 `user_id` 列
4. 为 `applications` 添加 `response_type` / `responded_at` 列
5. 创建 `user_preferences` 表（空 — 在 Web UI 中粘贴你的个人资料 YAML）
6. 所有 v0.5 命令继续工作；新功能为增量添加

无需手动操作。`default` 用户覆盖现有单用户设置。
