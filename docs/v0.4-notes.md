# JobBot v0.4 Release Notes

## Overview

v0.4 is a major release that transforms JobBot from a manual CLI tool into an automated job-search pipeline with a full web UI. Three pillars: pipeline automation, delete functionality, and resume composition — plus an audit quality gate, profile management, cover letter generation, and comprehensive AI interaction logging.

## New Features

### Pipeline Automation (`pnpm jobbot run`)

A single command processes all queued jobs through the full pipeline:

```
pnpm jobbot run                        # extract → score → compose → audit
pnpm jobbot run --step extract         # Extract only
pnpm jobbot run --step score           # Score only
pnpm jobbot run --step compose         # Compose only (tailor + render → PDF)
pnpm jobbot run --step audit           # Audit only (content + visual review)
pnpm jobbot run --job <id>             # Full pipeline for one job
```

- Rate limiting between LLM calls (1–2s delay)
- Progress logging per job
- Audit retry loop: if audit fails (< 70/100 or >1 page), auto-recomposes with feedback up to 3 times
- D-tier jobs (deal-breakers) are automatically skipped in Compose

### Pipeline as Background Service

The web UI can trigger pipeline runs:
- **▶ Run Pipeline** button on the pipeline page with stage dropdown
- Live progress polling via `GET /api/run/status`
- Per-job ▶ buttons on each queue item to advance a single job
- Per-step ▶ buttons let you process individual jobs through any stage

### Resume Composition

**`pnpm jobbot compose --job <id>`** — tailor + render in one step:
1. **Tailor** (DeepSeek LLM): Reads job description + candidate profile, selects relevant experience, reorders highlights, rephrases bullets with job keywords, generates professional summary
2. **Render** (LaTeX): Injects tailored data into `resumes/master.tex`, compiles to PDF via pdflatex
3. **Cover Letter** auto-generated during compose via DeepSeek LLM

- Individual `pnpm jobbot tailor --job <id>` and `pnpm jobbot render --job <id>` commands preserved for debugging
- Resume status set to `composed` on success
- PDF downloaded from the job detail page via the Composed stage panel

### Audit Quality Gate

**`pnpm jobbot audit --job <id>`** — two-phase AI review:

| Phase | Tool | Description |
|---|---|---|
| Content Audit | DeepSeek LLM | Reviews resume text against job description for accuracy, keyword alignment, content quality |
| Visual Audit | pdftoppm → PNG → Claude Vision | Checks layout, spacing, fonts, overflow, page breaks |

- **Pass threshold**: 70/100 overall score
- **1-page hard requirement**: Resume must be exactly 1 page. >1 page = immediate fail with condense instruction
- **Pass**: Status → `audited`, ready for Apply (v1.0)
- **Fail**: Writes audit feedback to `local/resumes/<id>-audit-feedback.json`, loops back to `scored` for re-compose with specific fix instructions

### Pipeline Stages (6 total)

```
Ingest → Extract → Score → Compose → Audit → Apply (v1.0)
```

Each stage shows live queue counts, expandable job lists, and per-job ▶ (advance) / ✕ (delete) buttons.

### Delete Functionality

- **CLI**: `pnpm jobbot delete --job <id>`, `--tier <tier>`, `--status <status>`, `--force`
- **Web UI**: Delete buttons on dashboard rows, job detail page, pipeline queue items
- Confirmation dialogs for all delete actions
- Cascading delete: removes related applications, resume_versions, and events

### Web UI

Served at `http://localhost:3000` (`pnpm jobbot ui`):

| Page | Description |
|---|---|
| Dashboard | Job list with tier badges, filters, sorting, inline delete |
| Job Detail | Score breakdown, pipeline tracker (clickable stages), event timeline, download PDF, regenerate stages |
| Pipeline | Visual architecture diagram with per-stage counts, job queues, Run button |
| Events | Full audit trail timeline — every state transition for all jobs |
| Profile | View/edit candidate.yaml, preferences.yaml, answers.yaml (manual + AI-assisted) |
| AI Log | Latest 500 AI call entries with input/output/cache tokens, duration, success/fail |

### Interactive Pipeline Stages

On the job detail page, each completed pipeline stage is clickable:
- **Extracted**: Shows title, company, location, ATS type
- **Scored**: Shows score, tier, full reasoning
- **Composed**: Download Resume + Download Cover Letter buttons
- **Audited**: Overall/Content/Visual scores with issue counts

Each stage has a **🔄 Regenerate** button with optional AI instruction input — resets the job back to before that stage and re-runs with custom guidance.

### Profile Management

- View and edit `candidate.yaml`, `preferences.yaml`, `answers.yaml` in the browser
- **Manual mode**: Direct YAML textarea editor with save
- **AI mode**: Describe changes in natural language → DeepSeek LLM updates the YAML
- API: `PUT /api/profile/:file`, `POST /api/profile/:file/ai-edit`

### AI Interaction Logging

Every LLM call is recorded to `local/logs/ai-YYYY-MM-DD.jsonl`:
- Timestamp, operation, model, provider, endpoint
- Input/output/cached token counts
- Duration, success/fail status
- Web UI viewer with filtering by operation and status

### Event Timeline

The `events` table is now populated on every state transition:
- `ingest` → `extract` → `score` → `compose` → `audit_pass`/`audit_fail` → `regenerate` → `delete`
- Full timeline page at `/events` with job and type filters
- Per-job timeline on the job detail page

### API Key Configuration

API keys moved from environment variables to `local/config.yaml` (gitignored):

```yaml
api_keys:
  deepseek: "sk-..."    # DeepSeek API key
  anthropic: ""         # Anthropic (Claude) API key (optional, for visual audit)
```

Environment variables still work as fallback. Template at `local.example/config.yaml`.

## Bug Fixes

- **Status tracking**: Extract and Score now correctly set `status` field (`extracted`, `scored`, `composed`, `audited`)
- **Pipeline queries**: Score=0 jobs (deal-breakers) are now correctly counted as scored, not queued
- **typst_path → tex_path migration**: Auto-migrates v0.3 database schema
- **LaTeX escaping**: Special characters (&, %, $, etc.) properly escaped in all injected text
- **Date formatting**: YYYY-MM dates converted to "Month Year" format in resume
- **Mustache template fixes**: Double-brace `{{key}}` matching preserves LaTeX argument delimiters

## System Dependencies Added

- `poppler-utils` — pdftoppm (PDF→PNG for visual audit), pdfinfo (page count)
- `python3-pip` + `PyMuPDF` — Python PDF-to-image fallback

Install via `bash scripts/setup.sh`.

## Breaking Changes

- Status values changed: `tailored` + `rendered` → single `composed`
- `resume_versions.typst_path` → `resume_versions.tex_path` (auto-migrated)
- D-tier jobs are skipped by Compose (only A/B/C advance)
- API keys now read from `local/config.yaml` first (env vars still work as fallback)
