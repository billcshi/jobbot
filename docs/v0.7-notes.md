# JobBot v0.7 Release Notes

## Overview

v0.7 is a **quality and polish** release focused on bug fixes, UI refinements, and pipeline reliability. No new major subsystems — instead, we tightened every existing feature: tier gating, resume ordering, download UX, audit committee scoring, and pipeline state management.

## New Features

### Tier-Based Pipeline Gating

The automatic pipeline now only processes **A and B** tier jobs. Tier C jobs remain in `scored` status for manual review. Tier D (deal-breakers) continue to be skipped entirely.

- **`runCompose()`** SQL gate: `tier IN ('A', 'B')` (was `tier != 'D'`)
- **`runAll()`** per-job check: skips C-tier with log message
- **Pipeline page** shows "eligible (A/B only)" with yellow "C manual" and red "D skipped" counters
- Manual actions (Re-compose buttons, stage-click popovers) bypass tier gates — user-initiated actions always proceed regardless of tier

### Descriptive PDF Download Filenames

Resume and cover letter downloads now use meaningful filenames instead of generic `resume.pdf`:

```
FirstNameLastName_Stripe_2026-06-13_v17.pdf
CoverLetter_FirstNameLastName_Stripe_2026-06-13.pdf
```

Format: `{FirstName}{LastName}_{Company}_{YYYY-MM-DD}_v{id}.pdf`

- Candidate name parsed from profile, company from job, date from `resume_versions.created_at`, version from `resume_versions.id`
- Fallback to `Candidate` / `Unknown` if profile data is missing
- File on disk remains `resume.pdf` — only the download attribute (browser-suggested filename) changes
- Stale `pdf_path` entries auto-detected: if the file on disk is missing, the download link is hidden and the DB record is cleaned

### Experience Ordering — Reverse-Chronological Enforcement

Three-layer defense ensures work experience is always in reverse-chronological order (most recent first):

1. **Prompt instruction** — tailor prompt explicitly requires reverse-chronological order
2. **Deterministic sort** — after LLM returns, `selected_experience` is forcibly sorted by start date (Present = Infinity, Month YYYY parsed to comparable values)
3. **Audit committee** — format reviewer has "Experience order (20%)" criterion; wrong order deducts 20 points

### Resume + Restart Pipeline Buttons

The job detail page now has two pipeline buttons instead of one:

| Button | Behavior |
|---|---|
| **▶ Resume** | Continues from the **current stage**, skipping already-completed ones |
| **↻ Restart** | Restarts from **extract** (scratch), re-doing everything |

The resume stage is auto-detected from `job.status`: `new → extract`, `extracted → score`, `scored → compose`, `composed → audit`, `audit_failed → compose`.

### Pipeline Task Pool — Auto-Cleanup

Completed tasks in the pipeline task pool now **fade out and disappear after 5 seconds** with a CSS opacity animation. Newly completed tasks get a subtle fade-in. Running, failed, and cancelled tasks remain visible. The task pool panel auto-hides when all tasks are gone.

## Bug Fixes

### Pipeline Web UI Showing "Idle" While Running

**Root cause:** `runExtract()`, `runScore()`, `runCompose()`, and `runAudit()` called `startStage()` but never `startPipeline()` — so `state.running` stayed `false`. The web UI polled `/api/pipeline/status` and saw `running: false` → displayed "Idle" even though work was happening.

**Fix:** `/api/run` endpoint now calls `state.startPipeline()` before launching per-stage runners and `state.finishPipeline()` in a `finally` block. Both calls are idempotent — safe even when `runAll()`/`runJob()` already call them internally.

### Dashboard Sort By Score — Wrong Order

**Root cause:** The sort query used `COALESCE(us.score, -1) DESC`. Jobs scored before v0.6 had `jobs.score` but no `user_scores` row, so the LEFT JOIN returned `NULL` → sorted as `-1` (bottom). But the display fell back to `jobs.score`, showing a high score at the bottom of the list.

**Fix:** Sort uses `COALESCE(us.score, j.score, -1) DESC` — falls back to `j.score` before `-1`. Tier filter uses `COALESCE(us.tier, j.tier)`. Display tier is now **derived from score** using canonical thresholds (A≥0.80, B≥0.65, C≥0.50, D<0.50), ensuring the tier badge always matches the numeric score regardless of what the LLM returned.

### Re-compose Buttons Not Working for Tier D Jobs

**Root cause:** The `run-from` endpoint had a tier D gate (`if (jobRow.tier === 'D') return`) that silently skipped compose for D-tier jobs. The 202 response was already sent, so the button appeared to work but nothing happened.

**Fix:** Removed the tier gate from `run-from`. The tier filter belongs in the automatic pipeline, not in explicit user actions.

### LaTeX Fix Now Opt-In

**Root cause:** `composeJob()` defaulted `fixLatex` to `true` (`opts?.fixLatex !== false`). Every automatic pipeline re-compose after audit failure also fixed LaTeX — wasting API calls and potentially overwriting good templates.

**Fix:** Changed to `opts?.fixLatex === true` — opt-in. Only the "Re-compose with TeX Fix" button sets `fixLatex: true`. The default pipeline and "Re-compose (Content Only)" do not fix LaTeX.

### Experience Out of Order in Rendered Resume

**Root cause:** The tailor LLM ordered experience positions by relevance, not by date. A current job (April 2025–Present) appeared after a past job (Sept 2023–June 2024).

**Fix:** Deterministic sort by `start` date after LLM returns (see Experience Ordering above).

### PDF Download Filename Containing Internal Slug

**Root cause:** `version_name` in `resume_versions` stored internal unique slugs like `tailored-v1-1781115024536`. This was used directly in the download filename.

**Fix:** Download filename now uses `resume_versions.id` (clean auto-increment integer) as the version identifier.

## Audit Committee Improvements

### Experience Ordering Check

The format reviewer (`audit-format.md`) now checks that work experience is reverse-chronological. Wrong order is a **20-point deduction** (new top criterion at 20% weight).

### Softened 1-Page Limit

The tailor prompt's hard constraint *"MUST fit on one letter-size page"* is now *"Aim for one page — the audit committee will score page count. Slightly over is better than crammed."* The format reviewer still enforces it via scoring (25%, -20 for >1 page), but it's now a judgment call rather than a cram-at-all-costs directive.

## Breaking Changes

- **Tier C jobs are no longer auto-composed.** The automatic pipeline skips C-tier. Use the job detail page's "▶ Resume" button to manually compose C-tier jobs.
- **LaTeX fix is opt-in.** After audit failure, the automatic re-compose no longer fixes LaTeX. Click "Re-compose with TeX Fix" to trigger LaTeX fixing manually.
