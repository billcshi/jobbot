# JobBot v0.7 发布说明

## 概述

v0.7 是一个**质量和打磨**版本，专注于 bug 修复、UI 改进和流水线可靠性。没有新增主要子系统——我们收紧并完善了每个已有功能：层级过滤、简历排序、下载体验、审查委员会评分和流水线状态管理。

## 新功能

### 基于层级的流水线过滤

自动流水线现在只处理 **A 和 B** 层级的工作。C 层级的工作保留在 `scored` 状态供人工审核。D 层级（硬性排除）继续完全跳过。

- **`runCompose()`** SQL 过滤：`tier IN ('A', 'B')`（原来是 `tier != 'D'`）
- **`runAll()`** 每个任务检查：跳过 C 层级并记录日志
- **流水线页面**显示"A/B only"，黄色"C manual"和红色"D skipped"计数器
- 手动操作（Re-compose 按钮、阶段点击弹窗）绕过层级过滤——用户主动触发的操作始终执行，不受层级限制

### 描述性 PDF 下载文件名

简历和求职信下载现在使用有意义的文件名，而非通用的 `resume.pdf`：

```
FirstNameLastName_Stripe_2026-06-13_v17.pdf
CoverLetter_FirstNameLastName_Stripe_2026-06-13.pdf
```

格式：`{名}{姓}_{公司}_{YYYY-MM-DD}_v{id}.pdf`

- 从个人资料解析候选人姓名，从职位获取公司，日期来自 `resume_versions.created_at`，版本来自 `resume_versions.id`
- 如果资料数据缺失，回退到 `Candidate` / `Unknown`
- 磁盘上的文件仍为 `resume.pdf`——只有下载属性（浏览器建议的文件名）改变
- 自动检测过时的 `pdf_path` 条目：如果磁盘上的文件不存在，下载链接被隐藏，数据库记录被清理

### 工作经历排序——反向时间顺序强制执行

三层防护确保工作经历始终按反向时间顺序排列（最近的在前面）：

1. **提示词指令**——定制提示词明确要求反向时间顺序
2. **确定性排序**——LLM 返回后，`selected_experience` 按开始日期强制排序（Present = 无穷大，Month YYYY 解析为可比较的值）
3. **审查委员会**——格式审查员有"经历排序（20%）"评分标准；顺序错误扣 20 分

### Resume + Restart 流水线按钮

职位详情页现在有两个流水线按钮而非一个：

| 按钮 | 行为 |
|---|---|
| **▶ Resume** | 从**当前阶段**继续，跳过已完成的阶段 |
| **↻ Restart** | 从头开始（extract），重新执行所有步骤 |

Resume 阶段根据 `job.status` 自动检测：`new → extract`、`extracted → score`、`scored → compose`、`composed → audit`、`audit_failed → compose`。

### 流水线任务池——自动清理

流水线任务池中已完成的任务现在**在 5 秒后淡出消失**，带有 CSS 透明度动画。新完成的任务有微妙的淡入效果。正在运行、失败和取消的任务保持可见。所有任务消失后，任务池面板自动隐藏。

## Bug 修复

### 流水线 Web UI 运行时显示"Idle"

**根本原因：**`runExtract()`、`runScore()`、`runCompose()` 和 `runAudit()` 调用了 `startStage()` 但从未调用 `startPipeline()`——因此 `state.running` 保持为 `false`。Web UI 轮询 `/api/pipeline/status` 看到 `running: false` → 显示"Idle"，即使实际工作在后台进行。

**修复：**`/api/run` 端点现在在启动各阶段运行器之前调用 `state.startPipeline()`，并在 `finally` 块中调用 `state.finishPipeline()`。两个调用都是幂等的——即使 `runAll()`/`runJob()` 已经内部调用过也没关系。

### 仪表板按分数排序——顺序错误

**根本原因：**排序查询使用 `COALESCE(us.score, -1) DESC`。在 v0.6 之前评分的工作有 `jobs.score` 但没有 `user_scores` 行，所以 LEFT JOIN 返回 `NULL` → 排序为 `-1`（排在最后）。但显示回退到 `jobs.score`，在列表底部显示高分。

**修复：**排序使用 `COALESCE(us.score, j.score, -1) DESC`——在 `-1` 之前回退到 `j.score`。层级过滤使用 `COALESCE(us.tier, j.tier)`。显示层级现在**根据分数计算**，使用标准阈值（A≥0.80, B≥0.65, C≥0.50, D<0.50），确保层级标签始终与分数匹配，无论 LLM 返回什么。

### Re-compose 按钮对 D 层级工作无效

**根本原因：**`run-from` 端点有一个 D 层级门控（`if (jobRow.tier === 'D') return`），对 D 层级工作静默跳过 compose。202 响应已经发送，所以按钮看起来正常但什么都没做。

**修复：**从 `run-from` 中移除了层级门控。层级过滤属于自动流水线，而非用户的显式操作。

### LaTeX 修复现在为选择加入

**根本原因：**`composeJob()` 默认 `fixLatex` 为 `true`（`opts?.fixLatex !== false`）。每次审查失败后的自动流水线重新 compose 也会修复 LaTeX——浪费 API 调用并可能覆盖好的模板。

**修复：**改为 `opts?.fixLatex === true`——选择加入。只有"Re-compose with TeX Fix"按钮设置 `fixLatex: true`。默认流水线和"Re-compose (Content Only)"不修复 LaTeX。

### 简历中工作经历排序错误

**根本原因：**定制 LLM 按相关性而非日期排序工作经历。当前工作（2025年4月至今）出现在过去工作（2023年9月–2024年6月）之后。

**修复：**LLM 返回后按 `start` 日期确定性排序（参见上面的经历排序）。

### PDF 下载文件名包含内部标识符

**根本原因：**`resume_versions` 中的 `version_name` 存储了内部唯一标识符，如 `tailored-v1-1781115024536`。这被直接用于下载文件名。

**修复：**下载文件名现在使用 `resume_versions.id`（简洁的自增整数）作为版本标识符。

## 审查委员会改进

### 经历排序检查

格式审查员（`audit-format.md`）现在检查工作经历是否为反向时间顺序。错误的顺序**扣 20 分**（新增的最高权重标准，占 20%）。

### 放宽一页限制

定制提示词中的硬性限制*"必须恰好一页"*现在改为*"目标是一页——审查委员会将评判页数。稍微超出一页比挤在一起好。"*格式审查员仍然通过评分来执行（25%，超过一页扣 20 分），但现在是判断而非硬性约束。

## 破坏性变更

- **C 层级工作不再自动 compose。**自动流水线跳过 C 层级。使用职位详情页的"▶ Resume"按钮手动 compose C 层级工作。
- **LaTeX 修复为选择加入。**审查失败后，自动重新 compose 不再修复 LaTeX。点击"Re-compose with TeX Fix"手动触发 LaTeX 修复。

## 无需数据库迁移

v0.7 不修改数据库架构。无需迁移。所有变更均为代码级别的修复和提示词优化。
