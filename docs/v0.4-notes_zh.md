# JobBot v0.4 发布说明

## 总览

v0.4 是一个重大版本更新，将 JobBot 从手动 CLI 工具转变为具有完整 Web UI 的自动化求职流水线。三大支柱：流水线自动化、删除功能和简历制作——外加审核质量关卡、个人资料管理、求职信生成以及全面的 AI 交互日志。

## 新功能

### 流水线自动化 (`pnpm jobbot run`)

一条命令处理队列中的所有职位：

```
pnpm jobbot run                        # 提取 → 打分 → 制作 → 审核
pnpm jobbot run --step extract         # 仅提取
pnpm jobbot run --step score           # 仅打分
pnpm jobbot run --step compose         # 仅制作（定制 + 渲染 → PDF）
pnpm jobbot run --step audit           # 仅审核（内容 + 视觉审查）
pnpm jobbot run --job <id>             # 对单个职位运行完整流水线
```

- LLM 调用之间的速率限制（1–2 秒延迟）
- 每个职位的进度日志
- 审核重试循环：如果审核失败（< 70/100 或超过 1 页），自动用反馈重新制作，最多 3 次
- D 级职位（不可接受的条件）在制作阶段自动跳过

### 流水线后台服务

Web UI 可触发流水线运行：
- 流水线页面上的 **▶ Run Pipeline** 按钮，带阶段下拉菜单
- 通过 `GET /api/run/status` 进行实时进度轮询
- 每个队列项上的 ▶ 按钮可推进单个职位
- 每步 ▶ 按钮可单独处理任一阶段的职位

### 简历制作

**`pnpm jobbot compose --job <id>`** — 定制 + 渲染一步完成：
1. **定制**（DeepSeek LLM）：读取职位描述 + 候选人资料，选择相关经历，重新排序亮点，用职位关键词改写，生成专业摘要
2. **渲染**（LaTeX）：将定制数据注入 `resumes/master.tex`，通过 pdflatex 编译为 PDF
3. **求职信**在制作过程中通过 DeepSeek LLM 自动生成

- 保留单独的 `pnpm jobbot tailor --job <id>` 和 `pnpm jobbot render --job <id>` 命令用于调试
- 成功后简历状态设置为 `composed`
- 通过制作阶段面板在职位详情页下载 PDF

### 审核质量关卡

**`pnpm jobbot audit --job <id>`** — 两阶段 AI 审查：

| 阶段 | 工具 | 描述 |
|---|---|---|
| 内容审核 | DeepSeek LLM | 对照职位描述审查简历文本的准确性、关键词匹配度、内容质量 |
| 视觉审核 | pdftoppm → PNG → Claude Vision | 检查布局、间距、字体、溢出、分页 |

- **通过阈值**：总分 70/100
- **1 页硬性要求**：简历必须恰好 1 页。>1 页 = 立即失败并附精简指令
- **通过**：状态 → `audited`，准备投递（v1.0）
- **失败**：将审核反馈写入 `local/resumes/<id>-audit-feedback.json`，循环回 `scored`，使用具体修复指令重新制作

### 流水线阶段（共 6 个）

```
录入 → 提取 → 打分 → 制作 → 审核 → 投递（v1.0）
```

每个阶段显示实时队列计数、可展开的职位列表以及每个职位的 ▶（推进）/ ✕（删除）按钮。

### 删除功能

- **CLI**：`pnpm jobbot delete --job <id>`、`--tier <tier>`、`--status <status>`、`--force`
- **Web UI**：仪表板行、职位详情页、流水线队列项上的删除按钮
- 所有删除操作均有确认对话框
- 级联删除：移除关联的 applications、resume_versions 和 events

### Web UI

通过 `http://localhost:3000` 访问（`pnpm jobbot ui`）：

| 页面 | 描述 |
|---|---|
| 仪表板 | 职位列表，含等级标签、筛选、排序、行内删除 |
| 职位详情 | 分数明细、流水线追踪器（可点击阶段）、事件时间线、下载 PDF、重新生成阶段 |
| 流水线 | 可视化架构图，含每阶段计数、职位队列、运行按钮 |
| 事件 | 完整审计追踪时间线 — 所有职位的每次状态转换 |
| 个人资料 | 查看/编辑 candidate.yaml、preferences.yaml、answers.yaml（手动 + AI 辅助） |
| AI 日志 | 最近 500 条 AI 调用记录，含输入/输出/缓存 token、耗时、成功/失败 |

### 交互式流水线阶段

在职位详情页上，每个已完成的流水线阶段均可点击：
- **已提取**：显示职位名称、公司、地点、ATS 类型
- **已打分**：显示分数、等级、完整推理
- **已制作**：下载简历 + 下载求职信按钮
- **已审核**：整体/内容/视觉分数及问题数量

每个阶段都有 **🔄 重新生成** 按钮，可输入 AI 指令 — 将职位重置回该阶段之前，使用自定义指令重新运行。

### 个人资料管理

- 在浏览器中查看和编辑 `candidate.yaml`、`preferences.yaml`、`answers.yaml`
- **手动模式**：直接 YAML 文本编辑器，可保存
- **AI 模式**：用自然语言描述更改 → DeepSeek LLM 更新 YAML
- API：`PUT /api/profile/:file`、`POST /api/profile/:file/ai-edit`

### AI 交互日志

每次 LLM 调用记录到 `local/logs/ai-YYYY-MM-DD.jsonl`：
- 时间戳、操作、模型、提供商、端点
- 输入/输出/缓存 token 数量
- 耗时、成功/失败状态
- Web UI 查看器，可按操作和状态筛选

### 事件时间线

`events` 表现在每次状态转换时都会填充：
- `ingest` → `extract` → `score` → `compose` → `audit_pass`/`audit_fail` → `regenerate` → `delete`
- 完整时间线页面位于 `/events`，可按职位和类型筛选
- 职位详情页上的单职位时间线

### API 密钥配置

API 密钥从环境变量迁移到 `local/config.yaml`（gitignored）：

```yaml
api_keys:
  deepseek: "sk-..."    # DeepSeek API 密钥
  anthropic: ""         # Anthropic（Claude）API 密钥（可选，用于视觉审核）
```

环境变量仍可作为备选方案。模板位于 `local.example/config.yaml`。

## Bug 修复

- **状态追踪**：提取和打分现在正确设置 `status` 字段（`extracted`、`scored`、`composed`、`audited`）
- **流水线查询**：Score=0 的职位（不可接受条件）现在正确计入已打分，而非排队
- **typst_path → tex_path 迁移**：自动迁移 v0.3 数据库结构
- **LaTeX 转义**：所有注入文本中特殊字符（&、%、$ 等）正确转义
- **日期格式化**：YYYY-MM 日期在简历中转换为"Month Year"格式
- **Mustache 模板修复**：双括号 `{{key}}` 匹配保留 LaTeX 参数分隔符

## 新增系统依赖

- `poppler-utils` — pdftoppm（PDF→PNG 用于视觉审核）、pdfinfo（页数统计）
- `python3-pip` + `PyMuPDF` — Python PDF 转图片备选方案

通过 `bash scripts/setup.sh` 安装。

## 破坏性变更

- 状态值更改：`tailored` + `rendered` → 单一 `composed`
- `resume_versions.typst_path` → `resume_versions.tex_path`（自动迁移）
- D 级职位被制作阶段跳过（仅 A/B/C 继续）
- API 密钥优先从 `local/config.yaml` 读取（环境变量仍可作为备选）
