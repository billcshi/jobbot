# JobBot v0.5 Release Notes

## Overview

v0.5 expands JobBot into a comprehensive Web-UI job-search platform with discovery, batch operations, market intelligence, and dashboard analytics. The web UI is now the **primary interface** — `pnpm jobbot ui` launches everything you need. CLI commands remain for scripting and automation.

## New Features

### Job Board Discovery (`pnpm jobbot discover`)

Search for jobs across multiple job boards:

```bash
pnpm jobbot discover --query "backend engineer" --location "Seattle"
pnpm jobbot discover --query "ml engineer" --source greenhouse --source lever
pnpm jobbot discover --query "sre" --location "remote" --ingest  # auto-add to pipeline
```

- **LinkedIn**: HTML scraping via cheerio — searches job listings with keyword + location filtering
- **Greenhouse**: Public board API (`boards-api.greenhouse.io`) — per-company search
- **Lever**: Public postings API (`api.lever.co`) — per-company search
- **Ashby**: Public API (`jobs.ashbyhq.com/api/nonuser`) — per-company search
- Fan-out to all enabled sources in parallel with `Promise.allSettled`
- Deduplication by URL
- `--ingest` flag auto-adds results to the pipeline
- Web UI integration: search form on the Add URLs page with inline "+" add buttons

### Batch URL Add

Add multiple job URLs at once — no more one-at-a-time copy-paste:

- **Web UI page** at `/add-urls`: paste URLs (one per line), preview ATS detection, add all at once
- **"Add & Run Pipeline"** button: adds URLs and immediately triggers full pipeline extraction
- **CLI**: `pnpm jobbot add-url <url1> <url2> <url3> ...` supports multiple positional args
- **API**: `POST /api/jobs/add-urls` and `POST /api/jobs/add-urls-and-run`
- Results display: new (✓), duplicates (⚠), errors (✕) per URL

### Job Market Intelligence

The `job_market_data` table is now populated automatically after every scoring run:

- **Salary ranges** — extracted from job descriptions via regex (`$120k–$180k` patterns), keyed by `salary_range.{title}.{location}`
- **Common requirements** — skill/technology frequency across all jobs (`common_req.{skill}`), using skills from your candidate profile
- **Title frequency** — normalized title distribution (`title_freq.{title}`)
- Confidence and sample_size track data reliability over time
- **CLI**: `pnpm jobbot market-data [--key <prefix>]` to view current intelligence
- **API**: `GET /api/market-data?key=<prefix>`
- Integrated into all scoring paths: `runScore()`, `runJob()`, server step handler, regenerate handler

### Dashboard Analytics

The dashboard now includes inline SVG analytics (no external chart library):

- **Tier Distribution** — horizontal bar chart showing A/B/C/D counts and percentages
- **Pipeline Funnel** — SVG funnel visualization: Ingested → Extracted → Scored → Composed → Audited, with proportional widths
- **Top Companies** — listing of companies with the most jobs in your pipeline
- All data from existing SQLite queries — lightweight and instant

### Resume Variants

Auto-select the best resume variant based on job title keywords:

- Reads available variants from `candidate.yaml` (`resume_variants` section)
- Keyword-based matching: backend, full-stack, frontend, ml, devops, mobile
- Title keywords weighted higher than description keywords
- Passed through `composeJob()` → `tailorJob()` → LLM prompt as focus instruction
- Falls back to `general` if no clear match

### Cover Letter Tones

Choose the tone of your AI-generated cover letters:

- **Professional** (default): Polished, balanced business tone
- **Enthusiastic**: Energetic, warm, shows genuine excitement
- **Concise**: Direct, short paragraphs, no filler — max 3 paragraphs

```bash
# CLI: auto-generates with default (professional) tone
pnpm jobbot cover-letter --job <id>
```

- **Web UI**: Tone dropdown on the job detail page before generating
- **API**: `POST /api/jobs/:id/cover-letter` with `{ tone: "professional" | "enthusiastic" | "concise" }`

### Scheduled Pipeline Runs

Automate the pipeline on a recurring schedule:

```bash
pnpm jobbot schedule --once                    # Run pipeline once
pnpm jobbot schedule --interval 360            # Run every 6 hours (Ctrl+C to stop)
```

- **In-server**: `POST /api/schedule/start` / `POST /api/schedule/stop` / `GET /api/schedule/status`
- Uses `setInterval` — no external dependency needed
- Runs the full pipeline (`runAll()`) on each tick

### Apply Step Research

Preparatory research for v1.0 apply automation — see `docs/apply-research.md`:

- **ATS form structures** documented for Greenhouse, Lever, Ashby, Workday, LinkedIn
- **Field mappings** catalogued: standard fields + EEO/demographics per platform
- **Adapter interface** designed: `AtsAdapter` with `canHandle()`, `detectForm()`, `fillField()`, `uploadResume()`, `submit()`
- **Implementation priority**: Lever → Greenhouse → Ashby → Workday
- **Anti-bot measures** identified: CAPTCHA, honeypots, Session timeouts
- All adapter stubs updated with v1.0 implementation notes

### LLM-Extracted Salary & Skills

The extraction step now uses DeepSeek to parse salary ranges and required skills directly from job descriptions — not just regex. Written to `job_market_data` during extraction (confidence 0.8) with regex as fallback for old jobs.

- **Salary**: LLM identifies `$120k–$180k` patterns with full context, handles non-standard formats
- **Skills**: LLM identifies technologies mentioned in the posting, not just from a fixed keyword list
- **Job detail page**: Per-job salary displayed prominently, skills shown as tag chips with LLM/regex source label
- **Per-job market data**: Queries `source = job_<id>` for this job's specific extracted data

### Profile AI-Edit Diff View

When editing profile YAML via AI, you now see a **side-by-side diff** instead of just the raw output:

- **LCS-based line diff**: Old YAML on the left, AI-proposed YAML on the right
- **Color highlighting**: Added lines in green, removed lines in red, unchanged in dimmed text
- **Change summary**: "+N added · −M removed" at the top
- **Scrollable panels**: Each side scrolls independently within a 500px container
- Apply or discard with a single click

### Configurable LLM Model

The DeepSeek model is now configurable via `local/config.yaml`:

```yaml
deepseek_model: deepseek-v4-pro  # default (best quality)
# deepseek_model: deepseek-v4-flash  # faster, cheaper
```

All LLM calls (extract, score, tailor, cover-letter, audit, profile AI-edit) read from this setting. No hardcoded model strings. `deepseek-chat` and `deepseek-reasoner` are deprecated upstream (sunset 2026/07/24).

### Bug Fixes

- **Delete FK constraint**: `deleteJob()` now properly cleans up `events` rows before deleting the job, fixing the "FOREIGN KEY constraint failed" error
- **Diff view scrolling**: Fixed `overflow: hidden` blocking scroll in the profile AI-edit side-by-side comparison

## Breaking Changes

None. All v0.4 commands and API routes continue to work. New features are additive.

## Migration from v0.4

No database migration needed. `job_market_data` data populates organically as you score jobs. Resume variants and cover letter tones are opt-in — existing behavior is preserved.
